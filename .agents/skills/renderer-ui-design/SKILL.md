# Renderer UI Design

将真实渲染器接入精致、克制的技术展示界面。参考风格是本 skill 随附的 PBRT Scene Lab 实例：**Rendering-first / Dark Neutral / Developer Tool / Precise Typography**。默认应用文案、工具提示、可访问名称、加载和错误状态均为英文；用户另有语言或品牌要求时以用户要求为准。原始场景数据不翻译、不改写。

## 先确定现有边界

阅读前端入口、组件、样式、状态管理、Canvas/Renderer 接口和现有验证命令，检查 Git 状态。复用原框架与控件体系，不为这个风格迁移框架。

先列出已有功能与状态所有权：加载、场景切换、相机、累积、曝光、分辨率、深度、导出、自检与资源释放。把按钮连回原有接口；缺少的能力不伪装成可用。不因 UI 改版添加 picking、重写 Parser / Scene IR / shader / renderer；后端变动仅按当前用户任务另行界定。新项目还未接入 renderer 时明确呈现未就绪状态，不用静态图片或假统计冒充渲染结果。

## 设计语言

采用中性炭黑背景、轻微面板层次、柔和细边框与一种低饱和强调色，默认 Sage Green。让渲染图像成为页面的主要色彩与视觉中心。不要用装饰卡片墙、强渐变、发光边框、夸张动画或第三方产品 Logo。

按需阅读 [设计系统与布局](references/design-system.md)，可从 [tokens.css](assets/tokens.css) 取样并映射到项目已有变量。它是起点，不是全局样式重置或必须覆盖的主题。优先复用已有字体/图标；否则使用 Inter / Geist 的系统回退、等宽数值字体和一致线宽的 SVG 图标。不要为字体或图标引入不必要的远程依赖。

## 两种工作区

### Showcase：默认入口

- 展示真实画面，默认隐藏 Explorer 与 Properties。顶部只放品牌、场景选择、Showcase / Inspect 与源码入口。
- 完整显示 Film / 输出图像，保持比例。不能通过裁切或拉伸减少留白。横图放在竖屏上产生的必要留白应接受。
- 在画面外围预留标题、工具栏和状态区域；尤其检查方形 Film 是否进入标题区。悬浮控件紧凑统一，曝光/采样等细项用 Popover 按需打开。
- 相机重置、暂停/继续、重新累积、设置、帮助、全屏按真实能力提供。图标按钮有英文 Tooltip、可访问名称和明显 Focus；宿主不允许全屏时提供可理解的反馈。
- HUD 仅显示真实且相关的信息。路径追踪可显示 SPP、输出尺寸、Triangle Count、Adapter；其他 renderer 换成实际可测字段。CPU 加载时间、GPU 时间与帧率必须区分，不展示占位性能数据。

### Inspect：开发者工作区

- Explorer / Viewport / Properties 职责分开，中间画面保持最大单块空间。侧栏可收起、可调整宽度；诊断放入默认关闭的底部 Drawer。
- Explorer 分组、搜索、类型筛选与数量统计对应实际场景。用有意义的名称或源文件名辅助识别，不能只有数百个无区别的网格标签。
- 大列表按可视区域虚拟化，保留选中状态与稳定 ID，提供空结果状态和键盘导航。不要通过 CSS 隐藏数千个已创建节点来冒充虚拟化；行高变化时同步调整索引算法。
- Properties 随选择展示类型、Source Location、Parameters、Transform、References 等结构化字段，纹理可展示真实预览与元信息。完整原始对象放到按需 Raw Data 标签页或弹窗。
- 不为展示美化而修改底层数值精度。长数组、矩阵、资源路径可展开、换行或局部滚动；完整原值始终可查看。没有编辑能力时明确只读。

## 保持渲染语义

- UI 模式、面板开合、搜索、选择节点、Raw Data 与窗口缩放不应重新初始化 Renderer、重载场景或无故清空累积。
- 区分 **CSS 显示尺寸 / GPU backbuffer / Camera 或 Film aspect**。显示容器改变时做等比 fit；若项目以固定预览分辨率采样，窗口缩放不必重建 backbuffer。若已有动态分辨率策略，沿用它的分配与相机更新规则。不要仅改 CSS 后就声称三者一致。
- 曝光沿用 renderer 约定；在显示阶段实现的曝光不重置线性累积。相机或采样设置改变应按既有规则 reset。深度、seed、目标采样、clamp 等只呈现真实支持的选项与边界。
- 场景切换同步默认值、手动覆盖值、Inspector、加载与错误状态。保留 generation / cancellation、buffer 释放、device-lost 等原有生命周期约定。
- 自动达到目标采样后，按钮和状态文字都应显示已暂停/达到目标，不能仍声称正在渲染。全屏失败、导出失败与 GPU 自检失败使用真实反馈，不伪造通过状态。

## 响应式与交互

建议从 ≥1440px 三栏、1100–1439px Inspector Drawer、<1100px 双侧按需 Drawer 开始，根据实际面板内容调整。移动端至少能看图、选场景和操作基本控件；不要强塞三栏。

窄屏 Drawer 与 Popover 避免相互遮住操作，关闭后恢复合理焦点。场景选择器有足够文字宽度，必要时顶栏明确分为两行；只看到下拉箭头不是可接受的移动布局。不要让长 JSON、路径、HUD 或工具栏造成文档横向溢出。

键盘快捷键避开输入框、浏览器和已有相机键位；说明作用范围。搜索、Tab、Escape、面板关闭与虚拟列表离屏导航应实际可用，不能只添加 ARIA 标签。

## 实施与验收

直接修改已连接 renderer 的项目，先完成可用的 Showcase，再接 Inspect 与诊断。按用户范围保留或提升已有交互，不停在设计稿。

运行项目现有的类型检查、必要回归与生产构建。用正确资源 base 打开生产预览；有浏览器能力时必须实际观察并截图，不能仅凭构建通过证明布局正确。具体操作清单见 [验证方法](references/validation.md)。

按需查看 [PBRT 案例与实际截图](references/pbrt-case.md)，用于理解风格和已发现的问题，不把该案例的场景、统计值、固定行高或 renderer 特性硬编码到新项目。

交付功能变更、真实截图、执行过的检查和未验证边界。实现这个 UI 的请求本身不授权创建公开仓库或发布；发布依照当前会话授权及项目现有流程处理，本 skill 不替代部署 skill。
